## 一、30 秒电梯版（先抛结论）

> CareerAgent 是一个面向技术岗位的 **agentic RAG 后端**，做简历和 JD 的智能匹配、项目相关性排序、简历真实性审计和面试备考。它的核心设计是**确定性内核 + 可选 LLM 层**——所有分数和排名都由确定性代码算出来，LLM 只负责抽取、建议和把结构化证据叙述成报告。一句话概括我的设计哲学：**让 LLM 解释证据，而不是取代分数。** 整个项目用 Docker 跑、490 个测试、96% 覆盖率。

## 二、2 分钟标准版（有故事线）

按"**问题 → 核心决策 → 怎么落地 → 怎么验证**"四段讲，这是工程叙事的黄金结构。

**① 问题（15 秒）**
> 简历-JD 匹配如果直接交给 LLM 端到端做，有三个致命问题：分数每次不一样没法复现、没法测试、还会幻觉——而招聘是个高风险、要可解释的场景，这些都不能接受。

**② 核心决策（30 秒）**
> 所以我定了一条架构原则：**确定性内核拥有所有数字，LLM 只在外围做增强**。内核负责解析、检索、打分、审计，全是确定性函数；LLM 层负责字段抽取、改进建议、报告叙述，而且每个 LLM 调用都有确定性兜底——没有 API key 整个系统照样跑。这条原则后来指导了每一个模块。

**③ 怎么落地（60 秒，挑 2~3 个亮点，别铺开）**
> - **检索**用了混合策略：手写 BM25 抓精确技术词，向量做语义匹配，RRF 融合，再用 cross-encoder 重排——两阶段检索，便宜的召回、贵的精排。
> - **Agent** 是我手写的 ReAct 循环，没用 LangChain，因为我要可控、可测试、provider 无关。它能调工具、能从错误中自我恢复、还能暂停问用户再恢复。
> - **可控性**是重点工程：LLM 输出走 schema 校验 + 纠错重试 + 确定性 fallback，把 LLM 当成一个不可靠组件来工程化。

**④ 怎么验证（15 秒）**
> 我没停在"我觉得这样好"。搭了评估 harness 跑消融实验，用 Recall/MRR/nDCG 量化每个检索组件的贡献；还用 LLM-as-judge 检查生成报告有没有编造证据外的东西。

收尾：
> 它现在是个 backend-first 原型，生产化的东西（持久化、鉴权、限流）我在 README 里都标了边界，没假装它是成品。

🪝 埋的钩子：手写 BM25（→ 公式）、RRF（→ 为什么不加权）、cross-encoder（→ bi vs cross）、手写 ReAct（→ 为什么不用框架）、纠错重试（→ 和普通重试区别）、ablation（→ 跑分细节）、"标了边界"（→ 怎么生产化，显成熟）。

## 三、埋钩子的艺术（主动引导面试官问你准备好的）

好的自述不是信息倾倒，是**布置一个让对方在你的主场提问的局**。技巧：

1. **说半句留半句**：讲"我手写了 BM25 而不是用库"，但不解释为什么——面试官几乎一定会问"为什么手写？"，这时你 K 主题的细节全接上了。
2. **抛术语不展开**：自然带出"RRF""cross-encoder 重排""corrective retry""HNSW"，每个都是你能深聊 5 分钟的，等他挑一个问。
3. **主动认边界**：讲"参数现在是手调的领域先验，更严谨该用标注数据学"——主动暴露局限 + 给出改进方向，比被问出来强得多，显得诚实且有判断力。
4. **用一个数字锚定可信度**：ablation 真实跑分（hybrid+rerank 的 nDCG 0.873 vs bm25 0.771，但纯 vector 的 Recall 反而最高 0.922）——能讲出"数据和我直觉不完全一致"的细节，可信度爆表。

## 五、容易翻车的点（提前想好）

- **"为什么不用现成框架（LangChain）？"** → 别贬低框架，讲**你的场景需要可控/可测试/provider 无关**，是取舍不是优越。
- **"这不就是调用 API 包了层壳？"** → 强调确定性内核才是主体，LLM 只是可选增强；分数、检索、审计、评估全是自己实现的工程。
- **"参数怎么定的？"** → 老实说手调的领域先验 + 主动提出可以数据驱动学习。**别硬编一个假理由**，面试官能看穿。
- **被问到不会的** → "这块我没深入，但我的思路是……"，展示思考方式比假装知道强。
